## @ansonlai/docx-redline-js v0.9.0

Version 0.9.0 has two themes.

- **Reject All always restores the source.** Every tracked operation is checked after it runs: Word's Reject All of
  the output must equal Word's Reject All of the input. The check now refuses by default.
- **Lists are real lists.** A new `list-format` operation turns typed headers into Word lists, changes a list's
  numbering format, and joins lists. Every change is a tracked property change that Reject All undoes exactly.

The CLI contract moves to version 9. The list and fidelity behavior was checked in desktop Microsoft Word 16 through COM
(Word is only a test tool; the package has no Word, COM or Office dependency at runtime).

**Upgrade if you convert headings to lists or change list numbering. Also upgrade if your integration depended on
operations succeeding even when their Reject All was wrong: such operations are now refused.**

### Compatibility and Migration

- **CLI contract version 9.** It adds the `list-format` operation type. An integration that never sends `list-format`
  can keep requiring version 8. New capabilities:
  - `revision-fidelity-v1`: the Reject All verifier and `--revision-fidelity`.
  - `list-conversion-diagnostics-v1`: list warnings and errors for text edits.
  - `paragraph-numbering-binding-v1`: `paragraph-format` `properties.numbering`.
  - `list-format-v1`: `list-format` `convert-plain`.
  - `list-format-change-v1`: `list-format` `change-format` and `join`.

  Negotiate only the capabilities you use. An older CLI refuses an unknown `type` or `list.mode` with
  `INVALID_OPERATION`, which is a safe failure.
- **Behavior changes callers may notice:**
  - **The Reject All verifier refuses by default.** An operation whose Reject All would not restore the source is
    not applied. It returns `REVISION_FIDELITY_VIOLATION` with:
    - a one-line message that names the invariant, the source paragraph (index and excerpt), the expected and actual
      results, and how to retry;
    - `violations[]`, `invariants` and `recovery.retryGuidance` for agents.

    The message also goes to `onWarn`, and compact CLI output keeps it. To opt out per call, pass
    `verifyRevisionFidelity: 'warn'` (apply and warn) or `'off'`; on the CLI use `--revision-fidelity
    <enforce|warn|off>`. The agent profile rejects `off`. A single-target untracked operation
    (`generateRedlines: false`) must leave every paragraph outside its target unchanged (`ACCEPT_NEIGHBORS`).
  - **Atomic batches that type list markers are refused.** Under the strict policy (`--profile agent`, `--atomic`,
    `atomic`, or `strictListConversion: true`), a text edit that types `1.`/`A.`/`-` onto a plain paragraph fails
    with `UNSUPPORTED_LIST_CONVERSION`. A retyped marker whose format differs from the list fails with
    `UNSUPPORTED_LIST_FORMAT_CHANGE`. Outside the strict policy these are the warnings `LIST_MARKER_NOT_BOUND` and
    `LIST_FORMAT_NOT_APPLIED`; before 0.9.0 they were a silent `ok`. Pass `listMarkers: 'literal'` when literal marker
    text is intended.
  - **Renamed recovery actions.** These now point at the new operation and carry `recovery.suggestedOperation`:
    - `UNSUPPORTED_LIST_CONVERSION` and `LIST_MARKER_NOT_BOUND`: `use_list_format_convert_plain` (was
      `apply_plain_text_or_convert_in_host`).
    - `UNSUPPORTED_LIST_FORMAT_CHANGE` and `LIST_FORMAT_NOT_APPLIED`: `use_list_format_change_format` (was
      `change_list_format_in_host`).

    `list-change` still never applies a format change itself.
  - **`NUMBERING_ID_CONFLICT`.** `ensureNumberingArtifactsInZip` always merges numbering through the single allocator
    merge. It ignores the `mergeNumberingXml` callback and no longer replaces an existing `numbering.xml`. An
    incoming `w:abstractNum` or `w:num` whose id already exists with different content throws `NUMBERING_ID_CONFLICT`;
    before, it silently bound new paragraphs to another list. `openDocx` also rejects output that introduces a
    dangling `numId`, `abstractNumId` or `ilvl`.
  - **Receipt kind change.** When a whole paragraph is deleted by an empty `modified`, its deleted paragraph mark is
    reported with receipt kind `del` (was `structural`). The explicit `1. Header` list conversion now also receipts its
    `w:pPrChange`.
  - **List-format batch rules.** A `list-format` `change-format`/`join` with `scope: 'list'` counts as a write to every
    item it rebinds. In the same batch, any other write to those items fails with `LIST_FORMAT_COMPOSITION_CONFLICT`,
    except a single-paragraph `redline`.
  - Text-equal letter, roman and bullet header conversions (`B. Header` -> `B. Header`) are now made in the same
    paragraph instead of as a deleted line plus an inserted line.
  - `paragraph-format` keeps the earliest same-author `w:pPrChange` snapshot. It refuses to overwrite another
    author's snapshot (`PARAGRAPH_FORMAT_REVISION_CONFLICT`). Unknown `paragraph-format` property keys warn
    `UNKNOWN_PARAGRAPH_FORMAT_PROPERTY`; a later minor release will reject them.

### 1. Revision Fidelity Verifier

After every tracked operation, `services/revision-fidelity-verifier.js` compares Word's Reject All of the output with
Word's Reject All of the source. It works on the live DOM, without extra serialization. It compares:

- paragraph count and order;
- canonical text, including breaks and tabs;
- paragraph properties and `numPr`;
- hyperlink, field and content-control membership.

The Word semantics come from `core/word-revision-semantics.js`, a projection checked against recorded Word 16 Reject
All and Accept All results.

Fixes found while making this the default (several by the new reject-roundtrip matrix, which applies generated
operations on both the bare runner and the packaged facade):

- Reject All and Accept All of the library now match Word for cell paragraph marks, deleted tables and the mark
  `rPr` of a `pPrChange`.
- Table reconciliation keeps untouched multi-paragraph cells.
- Text-to-table redlines track their rows, so Reject All removes the table.
- Reconstruction keeps `w:fldSimple`, hyperlink and content-control wrappers.
- Reconstruction tracks deleted breaks, tabs and inline objects.
- An explicit-start list conversion records its `w:pPrChange`.
- An explicit `1. Header` conversion works on a bare `document.xml`.
- Property readers ignore `pPrChange`/`rPrChange` snapshots (`core/current-properties.js`).
- Paragraph-mark revisions are built only in `engine/paragraph-mark-revisions.js`.
- Punctuation edits stay surgical: `agents and` -> `agents,` marks only the changed tokens.

### 2. Canonical List Operations (`list-format`)

```javascript
await doc.applyOperations([
  // Typed headers "A. Scope" .. "C. Fees" become a real A./B./C. list (markers are tracked deletions).
  { type: 'list-format', target: { exactText: 'A. Scope' }, targetEnd: { exactText: 'C. Fees' },
    list: { mode: 'convert-plain' } },
  // Bullets become 1., 2., 3. on a new definition that copies the list's levels and indentation.
  { type: 'list-format', target: { exactText: 'Photo identification' },
    list: { mode: 'change-format', format: 'decimal' } },
  // A later list continues an earlier one.
  { type: 'list-format', target: { exactText: 'Confidentiality' },
    list: { mode: 'join', continueFrom: { exactText: 'Termination' } } }
], { author: 'Editor' });
```

- **`convert-plain`** binds plain paragraphs whose text starts with a typed marker, in place:
  - Supported markers: `1.`, `1)`, `A.`, `a)`, `IV.`, `iv.`, `-` and `•`.
  - The marker becomes a tracked `w:del`, and the binding a tracked `w:pPrChange`.
  - The typed value is the item's start value. Consecutive values share one list.
  - `strip: 'none'` with `format` binds a paragraph without touching its text.
- **`change-format`** allocates a new definition. It copies the source levels, indentation and fonts and redefines
  one level. It then rebinds the list (`scope: 'list'`) or a range that runs to the end of the list
  (`scope: 'range'`, which continues the count). The shared definition is never edited.
- **`join`** binds a list to the `numId` of an earlier list, so it continues that count.
- **`paragraph-format.numbering`** binds a paragraph to an existing list (`{ numId, level }`) or removes its binding
  (`null`).
- **Changed-text headers:** a `redline` that keeps the typed marker exactly plus a `list-format` of the same paragraph
  can share one batch (`1. Old` -> `1. New`). The redline always runs first. Pairs that change the marker are
  refused with `LIST_FORMAT_COMPOSITION_CONFLICT`.

These shapes are refused rather than approximated:

- style-linked numbering;
- mid-list splits;
- shared abstract definitions;
- instance level overrides;
- markers inside hyperlinks, fields or pending revisions.

Every refusal has a specific code and recovery envelope (see the knowledge base). Start values are written on the new
definition: `w:start` for `change-format` and `w:startOverride` for `convert-plain`. In-session Word probes with nested
items found that `change-format` needs `w:start` and that `convert-plain` renders correctly with `w:startOverride`.

All numbering goes through one allocator, `services/numbering-allocation.js`, shared by the standalone runner and
`openDocx`.

### Known Limitations

- `list-format` `detach` and `materializeMarker` are not available. To remove a list binding, use `paragraph-format`
  with `properties.numbering: null`.
- Style-linked lists (heading numbering, list styles) and text-box list members are refused by `list-format`.
- Separate bare `applyOperationsToDocumentXml` calls that do not share `numberingXml`/`numberingIdState` can allocate
  the same numbering ids. This is now detected (`NUMBERING_ID_CONFLICT`), not remapped.
- A plain `redline` that reconstructs a paragraph can drop its `w14:paraId`. `list-format` keeps paragraph identity.
