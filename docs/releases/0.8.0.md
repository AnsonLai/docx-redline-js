## @ansonlai/docx-redline-js v0.8.0

Version 0.8.0 is a major architecture release that introduces the **Universal Document Facade & Zero-Node Architecture**. It eliminates all runtime Node.js built-in dependencies (`node:zlib`, `node:crypto`, `Buffer`) from complete-document manipulation (`openDocx`), enabling `@ansonlai/docx-redline-js` to run seamlessly across all JavaScript environments—including browser clients, Cloudflare Workers, AWS Lambda, Deno, Bun, and sandboxed workflow platforms like n8n Code nodes.

The engine remains strictly OOXML-based and host-independent. This release requires no Microsoft Word, Office automation, COM, or proprietary document APIs. Core mutation, reconciliation modes, validation, rollback, comments, and Accept/Reject semantics remain fully authoritative.

---

### Compatibility and Migration

- **Universal entry points:** `openDocx`, `DocxDocument`, and `computePackageRevisionToken` are now exported directly from the primary package entrypoint (`index.js`):
  ```javascript
  import { openDocx, applyRedlineToOxml } from '@ansonlai/docx-redline-js';
  ```
- **Backward compatibility for `@ansonlai/docx-redline-js/node`:** Existing Node.js callers importing from `@ansonlai/docx-redline-js/node` retain 100% API parity. The Node facade delegates to the universal implementation while preserving `Buffer` return values and argument compatibility (`Buffer instanceof Uint8Array`).
- **Standard `Uint8Array` binary interface:** Complete `.docx` files are now ingested and serialized canonically as `Uint8Array` across all runtimes. `doc.toUint8Array()` provides canonical serialization; `doc.toBuffer()` remains available for backward compatibility in Node.
- **Zero-setup XML provider:** `@xmldom/xmldom` is now a direct dependency with transparent runtime fallback. Manual `configureXmlProvider` calls are no longer required in Node or sandboxes.
- **Standalone sandbox bundles:** Added the `@ansonlai/docx-redline-js/bundle` conditional export providing zero-dependency single-file bundles in both ESM (`dist/docx-redline.bundle.js`) and CommonJS (`dist/docx-redline.bundle.cjs`).
- **CLI contract remains version 8:** All command shapes, JSON schemas, flags, and error recovery contracts remain unchanged.

### 1. Universal Document Facade (`openDocx`)

Complete-document operations previously required Node.js due to reliance on `node/docx-document.js`. In v0.8.0, complete-DOCX lifecycle operations have moved to `document/docx-document.js` and are exported directly from root `index.js`.

Any modern JavaScript runtime can open, inspect, modify, and serialize `.docx` archives directly:

```javascript
import { openDocx } from '@ansonlai/docx-redline-js';

// Open from Uint8Array, ArrayBuffer, or Buffer
const doc = openDocx(docxBytes);

// Inspect paragraphs, headings, comments, and revision tokens
const inspection = doc.inspect();

// Apply document operations with atomic rollback and validation
const result = await doc.applyOperations([
  {
    type: 'replace',
    target: { paragraphId: inspection.paragraphs[0].paragraphId },
    modified: 'Updated clause text'
  }
], { author: 'AI Redliner' });

if (result.written) {
  // Export canonical Uint8Array
  const outputBytes = doc.toUint8Array();
}
```

### 2. Zero-Node ZIP Container (`fflate`)

The internal ZIP reader/writer in `node/zip-archive.js` previously relied on `node:zlib` (`deflateRawSync`, `inflateRawSync`), which prevented execution in browser workers and serverless sandboxes where Node built-ins are prohibited.

v0.8.0 replaces `node:zlib` with `fflate` (`document/zip-archive.js`):
- **Zero Node built-ins:** Uses standard `Uint8Array`, `DataView`, `TextEncoder`, and `TextDecoder`.
- **Full OOXML parity:** Retains bitstream compatibility, OPC part normalization, CRC-32 checksum calculation, and corrupt archive guards.
- **Lightweight footprint:** `fflate` adds under 15 KB gzipped to the bundle with zero transitive dependencies.
- **Backwards compatible:** `node/zip-archive.js` re-exports the universal implementation while returning `Buffer` for existing Node-specific callers.

---

### 3. Pure-JS Synchronous SHA-256

Revision tokens provide cryptographic optimistic concurrency control across document operations. Previously, `node/docx-document.js` imported `node:crypto` (`createHash`) to compute package revision tokens.

v0.8.0 introduces a dependency-free, pure-JS FIPS 180-4 SHA-256 implementation in `core/sha256.js`:
- **Fully synchronous:** Computes revision tokens synchronously without forcing asynchronous cascades across synchronous inspection APIs.
- **Deterministic parity:** Verified against standard NIST test vectors (empty string, short phrases, multi-block payloads) with exact bit-for-bit parity against `node:crypto`.
- **Runtime agnostic:** Executes in any environment supporting standard typed arrays.

---

### 4. Transparent XML Provider Fallback

Previous versions required explicit provider injection (`configureXmlProvider({ DOMParser, XMLSerializer })`) when running outside browser environments.

`adapters/xml-adapter.js` now features intelligent runtime auto-resolution:
1. **Host-provided DOM:** If `globalThis.DOMParser` and `globalThis.XMLSerializer` exist (browsers, Deno, headless DOM environments), they are used automatically.
2. **Transparent Pure-JS fallback:** If absent (Node.js, edge workers, sandboxed VMs), the adapter falls back transparently to pure-JS `@xmldom/xmldom`.
3. **Explicit override:** `configureXmlProvider` remains available for consumers who wish to inject custom parser/serializer implementations.

---

### 5. Zero-Dependency Standalone Sandbox Bundles

For restricted execution environments (such as **n8n Code nodes**, **Cloudflare Workers**, **AWS Lambda**, and **QuickJS** sandboxes) where installing npm dependencies or linking peer modules is restricted or complex, v0.8.0 provides self-contained standalone bundles:

- `dist/docx-redline.bundle.js`: Standalone zero-dependency ESM bundle.
- `dist/docx-redline.bundle.cjs`: Standalone zero-dependency CommonJS bundle.

Both bundles inline `fflate`, `diff-match-patch`, and `@xmldom/xmldom` with `platform: 'neutral'`, containing **zero external imports and zero Node built-ins**:

```javascript
// Available via conditional package exports:
import { openDocx } from '@ansonlai/docx-redline-js/bundle';
// Or in CommonJS / n8n Code nodes:
const { openDocx } = require('@ansonlai/docx-redline-js/bundle');
```
