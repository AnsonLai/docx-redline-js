## @ansonlai/docx-redline-js v0.11.1

Version 0.11.1 is a fix release. It has no new APIs, and the CLI contract stays at version 9 with no capability changes.

- **Footnote and endnote references are kept by text edits (GitHub #6, #7, #8).** A tracked edit could drop the
  reference after an edited sentence, so Accept All lost the footnote while Reject All looked correct. A new verifier
  check now refuses any edit that would lose one.
- **Word can reject edits at the end of a document cleanly.** Appending paragraphs after the last paragraph, or
  turning the last paragraph into a list, no longer tracks the document's final paragraph mark. Word's Reject All
  cannot remove that mark, so it left an empty paragraph behind.
- **`convert-plain` refuses soft-break markers.** A paragraph like `A. …<w:br/>B. …<w:br/>C. …` is refused instead of
  becoming one list item that keeps the B and C lines as text.

**Upgrade if your documents have footnotes or endnotes, if you append paragraphs or lists at the end of a document or a
table cell, or if you use `list-format` `convert-plain`.**

---

### Compatibility and Migration

- **CLI contract version 9 (unchanged).** No capability is added or removed. No new exports.
- **Behavior changes callers may notice:**
  - **A new revision fidelity invariant, `ACCEPT_NON_TEXT_CONTENT`.** Tracked and untracked operations are refused with
    `REVISION_FIDELITY_VIOLATION` when Accept All of their output would lose a footnote or endnote reference (compared
    by id), a drawing (`w:drawing`, `w:pict`) or an embedded object (`w:object`) of the source. Explicit deletions are
    exempt: an empty `modified`, an all-empty `modified` array, or a `delete` operation. Each violation names the
    content (`content`, for example `footnoteReference:1`) with expected and actual counts and
    `source.sourceParagraphIndex`. `w:sym` is not covered: it is a character that plain text carries. If you map
    invariants to messages, add this one.
  - **`convert-plain` refuses soft-break markers.** `LIST_MARKER_UNSUPPORTED` with `reason: 'soft-break-markers'` (plus
    `marker`, `lineMarker`, `lineIndex`, `paragraphIndex`, `targetExcerpt`) when a later `w:br` or `w:cr` line of a
    target paragraph, or of any paragraph in a `targetEnd` range, starts with a typed list marker of any family.
    `recovery.action` is `change_request` and the hint says to split the paragraph at its soft line breaks first.
    Nothing is written. Soft-break lines without a marker still convert as continuation lines, and `strip: 'none'` is
    unaffected.
  - **Paragraph-mark markup changed for appends.** Appending paragraphs after a target now tracks the target's mark
    (Word's "Enter at the end of the target"), not the new last paragraph's. At a container's end, a list regeneration
    joins the original's deleted text into the last new paragraph, with a `w:pPrChange`. Accept All and Reject All give
    the same results as before. Code that counts `w:ins`/`w:del` markers will see different numbers; code that checks
    the Accept All and Reject All views will not.
- No defaults change.

### 1. Footnote and endnote references

The reconstruction route turns each reference into a placeholder that plain replacement text cannot carry. It put a
reference back only when all the text before it, or all the text after it, was unchanged. Otherwise it deleted the word
before the reference together with the reference run and reinserted the word alone. Reported cases, all returning
status `ok` on 0.11.0:

| Case | Shape | References: source → Accept All |
|---|---|---|
| #6 | Reference at the end of the paragraph; the first words are edited | 1 → 0 |
| #7 | A bookmark around the first sentence, then a reference; the second sentence is edited | 1 → 0 |
| #8 | Five sentences, each followed by a reference; the first sentence is edited | 5 → 1 |

Now each reference is mapped through a semantic diff of the old and new text and kept at its boundary:

- Only the edited words change. #8 now has one deletion instead of one per reference.
- When the words just before a reference are replaced, the reference follows the replacement
  (`Friday¹.` → `Monday afternoon¹.`).
- Text inserted right after a reference no longer inherits its superscript formatting.
- Bookmarks (`w:bookmarkStart`, `w:bookmarkEnd`) are zero-width, so they no longer cause the words around them to be
  deleted and reinserted. In #7 the untouched first sentence now has no revisions.
- A `{{__FN_id__}}` or `{{__EN_id__}}` token in `modified` still places a reference explicitly.

Untracked edits (`generateRedlines: false`), localized `replacements` and `openDocx` behave the same way.

### 2. Paragraph marks at the end of a container

Word cannot reject a tracked insertion on the last paragraph mark of the body or of a table cell. When the add-in
inserted such a package with `insertOoxml(..., 'Replace')`, Reject All left an extra empty paragraph. Two routes did this:

- **Appending after a target.** A redline that appends paragraphs after its target (`'Last paragraph.\nAppended.'`)
  tracked the new last paragraph's own mark. It now follows Word's model: the target's mark is the inserted break, new
  paragraphs before the last track their own marks, and the last one inherits the target's original mark with its
  paragraph properties and their history (an existing mark insertion keeps its id and author; a `w:pPrChange` is moved,
  not copied). This applies in both `structuredContent` modes. Inserting before the target is unchanged.
- **List regeneration of a container's last paragraph.** A structured redline that regenerates the last paragraph as a
  list (`'Last.\n1. Item'`, `'1. Last.\n2. Next'`, a changed target plus typed items), or a `targetEnd` range ending
  there replaced by a list, ended with an inserted-mark paragraph after the deleted original. Now the original's
  deleted text joins the last new paragraph, which keeps the untracked mark and records the original paragraph
  properties (the oldest snapshot, if the source already had one) in a tracked `w:pPrChange`. Receipts drop the two
  removed mark ids. Mid-document edits are unchanged.

### 3. `convert-plain` and soft line breaks

```javascript
// One paragraph: "A. The Disclosing Party possesses…" <w:br/> "B. The Parties desire…" <w:br/> "C. …"
const result = await doc.applyOperations([{ type: 'list-format', target, list: { mode: 'convert-plain' } }]);
// result.status === 'error'; error.code === 'LIST_MARKER_UNSUPPORTED', error.reason === 'soft-break-markers'
```

Before 0.11.1 this stripped only `A.`, bound the whole paragraph as one list item labelled A., and reported success.
Split the paragraph into one paragraph per marker, then convert the range.

### Upgrading from 0.11.0

1. Pin 0.11.1.
2. Map `ACCEPT_NON_TEXT_CONTENT` if you translate fidelity invariants into messages. Treat it like the other
   invariants: retry smaller (for example `replacements`), and report it if it is refused again.
3. Map `LIST_MARKER_UNSUPPORTED` with `reason: 'soft-break-markers'` to "split the paragraph first" if you show list
   refusals to users.
4. If you worked around lost footnote references or the extra empty paragraph after Reject All, remove the workaround.
