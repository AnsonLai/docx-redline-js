## @ansonlai/docx-redline-js v0.6.0

This milestone release makes complete-document redlining substantially easier
and faster for AI agents while strengthening the library's fail-closed OOXML
safety model. Version 0.6.0 adds caller-order-independent batch targeting,
machine-actionable recovery plans, a compact stdin-based agent CLI workflow,
explicit restoration of foreign-deleted paragraphs, safer editing inside
cross-author revisions, self-describing bounded inspection, baseline-aware
validation, and a smaller published package with curated agent documentation.

The implementation remains an OOXML-only engine. It does not require Microsoft
Word, Office automation, COM, or a proprietary document API at runtime.

### Breaking Changes & Migration

- **Compact CLI mutation results (contract version 7)**: `apply`, `accept`,
  `reject`, and `delete-comments` no longer print complete OOXML/package payloads,
  full inspection data, or unbounded validation arrays. Read `completion`,
  `written`, `outputPath`, `status`, per-operation `results`, `receipts`, and the
  compact validation summary instead. Integrations that require the complete
  in-memory result should use the Node facade.
- **CLI capability negotiation**: Wrappers that pin the machine-readable CLI
  contract should require only the capabilities they use. Version 0.6.0 reports
  contract version 7 with command-help, contextual/bounded inspection,
  human-reference, compact-mutation, complete-success, stdin,
  `agent-safety-profile-v2`, `deduplicated-cli-receipts`,
  `compact-cli-json-v1`, source-binding, and recovery capabilities.
- **Agent profile composition**: `--profile agent` no longer selects atomic
  execution. It retains progressive execution and the ordinary revision policy
  unless `--atomic` or `--existing-revisions` is passed deliberately. Skills
  that assumed the version-5 atomic preset must add `--atomic` explicitly.
- **CLI receipt location**: Compact CLI operation results no longer repeat
  `results[i].receipt`; consume the ordered top-level `receipts` array. Full Node
  facade and standalone-runner receipt shapes are unchanged.
- **Batch conflicts fail before mutation**: Operations that write incompatible
  changes to the same source paragraph, mix unsafe formatting and text writes,
  or mutate one captured target through multiple consumers are rejected during
  batch compilation. Consolidate competing desired texts or express a genuine
  created-content dependency explicitly; do not rely on caller ordering.
- **Restore targeting uses the rejected view**: `type: "restore"` now defaults to
  the rejected document view, where the source text of a wholly deleted
  paragraph exists. Re-extract restore descriptors from the exact input package
  rather than reusing accepted-view or stale descriptors.

### Agent Workflow & Performance

- **Self-describing command help**: Global JSON help lists commands, while
  `<command> --help` returns only that command's flags, aliases, behavioral
  notes, exit codes, documentation routes, and bounded examples. `apply` help
  includes canonical redline, whole-paragraph comment, and rejected-view
  restore operation shapes.
- **One-turn contextual discovery**: Case-insensitive `extract`/`inspect`
  searches accept `--around` (`--context` or `-C`) and distinguish direct hits
  from surrounding context. `--limit` and `--after` page direct matches;
  unscoped CLI inspection defaults to 20 records and a 48 KiB soft JSON budget,
  while explicit `--all` retains full inspection. Returned targets remain whole
  and include human-facing provision/heading references.
- **Caller-order-independent batches**: Strong targets are resolved once against
  the immutable batch-start document and bound to rollback-aware session
  identities. Independent later paragraphs remain targetable after earlier
  splits, insertions, or index shifts, eliminating manual bottom-up sorting for
  ordinary batches.
- **Machine-actionable recovery**: Operation, package-facade, CLI, and sample
  session failures now include stable recovery metadata such as stage, category,
  action, retry safety, reinspection requirements, authorization requirements,
  bounded target context, and an original-versus-output retry plan.
- **Complete-success execution**: `apply --require-complete` returns exit code 3
  for progressive partial results. `--profile agent` enables that behavior
  without choosing atomic execution or a special existing-revision policy;
  explicit policy flags compose with the profile and appear in
  `effectiveOptions`.
- **Operations through stdin**: `--operations -` accepts a UTF-8 operation array
  or `{ "operations": [...], "expectedRevision": "..." }` envelope, removing
  the temporary `operations.json` file from shell-agent workflows.
- **Smaller successful mutation output**: CLI JSON carries each receipt once at
  the top level, removes exact-match diagnostics, and summarizes successful
  space-equivalent matching. `--compact` emits one-line JSON when provider-visible
  bytes matter. Errors retain bounded corrective evidence.
- **Tiered documentation**: The ordinary agent contract is now contained in a
  sub-600-word fast start, while `AGENTS.md` is a compact routing card that sends
  advanced topics to the full knowledge base. A packaged skill-authoring
  contract separately defines invariants, policy choices, transports, recovery,
  capability negotiation, and user-facing references.
- **Development session demonstration**: The repository includes a thin example
  showing opaque revision-bound handles, context-window inspection, and
  localized edit compilation. It remains a test/demo integration and is not
  shipped as part of the core package or presented as a new runtime abstraction.

The measured repository workflow reduced ordinary agent instructions from
2,023 to 349 words (82.75%), reduced the shell workflow from three calls to two
(33.33%), and reduced localized session request payloads by 82.22–89.96%
against canonical stateless Node envelopes. These are protocol and native
runtime measurements; they do not estimate provider/model thinking time.

### Revision Safety & Restoration

- **Explicit paragraph restoration (`type: "restore"`)**: Counterpropose a
  foreign-deleted paragraph or contiguous range as separately tracked sibling
  content without accepting, removing, or rewriting the original reviewer's
  deletion. Fresh paragraph identities and sanitized inherited formatting are
  generated automatically.
- **Deleted-section insertion**: Rejected-view `insert` operations can place new
  tracked text at an exact anchor inside another author's deleted content using
  Word-native sibling revision carriers. Ambiguous anchors and unsupported
  structural boundaries continue to fail closed.
- **Foreign deletion resurrection guard**: A normal non-empty paragraph edit can
  no longer accidentally revive a paragraph whose content and paragraph mark
  were deleted by another author. The operation returns
  `FOREIGN_PARAGRAPH_MARK_DELETION` with the owning author.
- **Cross-author slicing hardening**: Character-local source offsets, refreshed
  right-to-left span application, and stable insertion anchors preserve foreign
  authorship across NBSP changes, hyperlinks, repeated phrases, stacked
  revisions, and multiple edits within one run.
- **Comment preservation**: Unsafe deletion or same-author merging across
  commented content remains fail-closed so reviewer anchors and definitions are
  not silently orphaned.

### Validation & Fidelity

- **Baseline-delta validation**: Existing defects in a source package remain
  visible but no longer block unrelated safe work. A transaction fails only when
  it adds a new validation issue or creates an invalid mutation envelope.
- **Revision identity sanitation**: New paragraphs, lists, and reconstructed
  content inherit effective formatting without copying historical revision
  descendants. Duplicate revision IDs are detected before an operation commits.
- **Source-truth text alignment**: Target matching may treat ordinary spaces and
  NBSPs as equivalent, but mutation offsets are always calculated from the exact
  accepted source text. Mismatch diagnostics include the first differing code
  points and bounded target context.
- **Transactional guarantees retained**: Strict targets, package revision
  tokens, operation savepoints, atomic rollback, mutation receipts, and
  pre-commit output reconciliation remain enforced by the core apply path.

### Packaging

- The npm package now includes the compact agent guide, full agent knowledge
  base, testing guide, operation JSON schema, and agent rollout audit.
- Internal plans, the large test dashboard, historical validation reports, the
  development agent example, and agent benchmark scripts are excluded.
- The verified tarball contains 148 files and is approximately 1.06 MB packed,
  down from approximately 10.2 MB before documentation narrowing.
- `diff-match-patch` remains the sole production npm dependency. It is embedded
  in the browser bundles. The Node facade and CLI use the optional
  `@xmldom/xmldom` peer plus Node's built-in `node:zlib` ZIP implementation.

### Install

```bash
npm install @ansonlai/docx-redline-js@0.6.0
```

CDN (ESM):

```html
<script type="module" src="https://cdn.jsdelivr.net/npm/@ansonlai/docx-redline-js@0.6.0/dist/docx-redline-js.esm.min.js"></script>
```

For agent-driven editing, start with `AGENTS.md` or
`docs/AGENT_FAST_START.md` in the installed package.
