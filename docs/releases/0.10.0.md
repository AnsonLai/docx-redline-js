## @ansonlai/docx-redline-js v0.10.0

Version 0.10.0 is a small, additive release. It adds two things:

- **`existingRevisions: 'auto'`.** The policy is chosen per target: merge the operation author's own history, and slice
  around another reviewer's.
- **`compareDocumentInspections`.** It checks that a committed document matches the one that was prepared.

It also fixes underscore runs (signature and date lines) that collapsed to a single `_`.

The CLI contract stays at version 9. The new policy is advertised as the capability `existing-revisions-auto-v1`.

**Upgrade if you choose an existing-revision policy per paragraph yourself, if you write prepared packages through a
host API and want to verify the result, or if your documents contain `_____` blanks.**

---

### Compatibility and Migration

- **CLI contract version 9 (unchanged).** New capability:
  - `existing-revisions-auto-v1`: `existingRevisions: 'auto'` and `--existing-revisions auto`.

  Negotiate it only if you send `auto`. An older CLI refuses `auto` with `INVALID_OPERATION`, which is a safe failure.
- **Behavior changes callers may notice:**
  - **Underscore emphasis follows CommonMark flanking rules.** `__x__` and `_x_` become bold and italic only when the
    delimiters are not intraword, not part of a longer underscore run, and not next to whitespace on the inside. So
    `_____`, `______Date______` and `file_name_here` stay literal text. `a __bold__ b` and `an _italic_ word` still
    format. `*` and `**` are unchanged.
  - **A caller's `structuredContent: false` is plain text.** On a `redline` or `replace` (per operation, or as the batch
    option), inline Markdown markers (`**`, `__`, `_`, `~~`, `++`) are now kept literally instead of becoming
    formatting. If you relied on `structuredContent: false` to apply inline bold or italic, pass `true` (the default)
    instead.
- No defaults change. `existingRevisions` still defaults to `'merge-same-author'`.

### 1. `existingRevisions: 'auto'`

```javascript
await doc.applyOperations(operations, { author: 'Editor', existingRevisions: 'auto' });
```

For each target, `auto` resolves to:

- `'merge-same-author'` when the target has no tracked changes, or only the operation author's;
- `'slice-cross-author'` otherwise (unattributed changes count as another author's).

A `targetEnd` range resolves over every paragraph in it, so a plain first paragraph does not hide another reviewer's
insertion later in the range.

It is accepted per operation, per batch, by `applyRedlineToOxml` and as `--existing-revisions auto`.
`preflightOperations` reports the resolved policy for each operation. `resolveExistingRevisionsPolicy(policy, node,
author)` is exported from the root for hosts that need the same decision.

`auto` opts into cross-author slicing wherever it is needed. Choose it only when editing inside other reviewers'
pending insertions is intended for the whole batch. It never accepts or rejects anyone's revisions.

### 2. Comparing inspections

```javascript
import { inspectDocumentParts, compareDocumentInspections } from '@ansonlai/docx-redline-js';

const check = compareDocumentInspections(inspectDocumentParts(preparedParts), inspectDocumentParts(committedParts));
// { matches: boolean, differences: [{ path, expected, actual }] } (at most the first 10 differences)
```

The comparison looks at what a reader and a reviewer see:

- paragraph text;
- table position;
- list label;
- review segments (adjacent segments of one kind and author are merged);
- comments with their thread parents and resolved state.

It ignores revision ids, dates, rsids, paragraph ids and run boundaries, which hosts regenerate on write.
`inspectionReviewShape(inspection)` returns the normalized shape used for the comparison.

### Fixed since 0.9.0

Reported by the Word add-in:

- **Literal underscore runs collapsed to `_`.** A signature line such as `_________________________` became a single
  `_` in Accept All after a table reconciliation or a plain-text paragraph rewrite. Fixed by the CommonMark flanking
  rules and the plain-text `structuredContent: false` contract above. Internal library calls that pass
  `structuredContent: false` (the table-append heuristic and restoration templates) still parse inline Markdown; only a
  caller's `structuredContent: false` is plain text.

Found while testing this release:

- **Comment reply paraIds could collide with body paragraphs.** `applyCommentReplyToParts` (and the `comment_reply`
  operation) is meant to avoid every `w14:paraId` in the package, but its body scan used a regex with a literal backspace
  character where `\b` was intended, so body ids were never collected. A reply could reuse a body paragraph's id.
- **Test lanes that were silently no-ops now run.** The same backspace defect had disabled the reject-roundtrip matrix's
  revision-identity cross-check for untracked edits, and the matrix never applied its `RECEIPT_RECONCILIATION_FAILED`
  gate. Both run again and pass. The Reject All verifier's numbering check now uses its memoized definition parser,
  which had never been wired in.

### Upgrading from 0.9.0

1. Pin 0.10.0.
2. If you pick `merge-same-author` or `slice-cross-author` per paragraph from its revision authors, you can send
   `existingRevisions: 'auto'` instead. Require the `existing-revisions-auto-v1` capability when you do.
3. Audit call sites that pass `structuredContent: false` and expect inline Markdown formatting.
