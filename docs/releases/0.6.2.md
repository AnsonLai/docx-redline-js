## @ansonlai/docx-redline-js v0.6.2

Version 0.6.2 delivers targeted CLI discovery refinements to eliminate common
friction points observed during real-world AI agent execution. It adds smart
alternate-view search guidance when queries target deleted clauses, and updates
CLI help documentation links to canonical repository URLs to prevent wasteful
filesystem scans in containerized environments.

The document engine remains OOXML-only and host-independent. This release does
not change tracked-change generation, reconciliation, ZIP handling, package
validation, rollback, comment preservation, or Accept/Reject semantics. It
requires no Microsoft Word runtime, Office automation, or COM interop.

---

### Key Improvements

#### 1. Smart Alternate-View Search Guidance (`selection.hint`)

* **The Problem:** In a redlined document, deleted text is absent from the
  default `accepted` view (`exactText: ""`). When an AI agent is instructed to
  *"restore Section 3.2"*, it often begins with an ordinary
  `extract --search "3.2"` query without passing `--view rejected`. Because the
  default view is `accepted`, the CLI returns `totalMatches: 0`. In real-world
  agent transcripts, this triggered multi-turn "ghost hunts"—agents searched for
  adjacent sections (e.g. 3.1), guessed paragraph ranges, diffed all three views
  in loops, or wondered if paragraph indexes were corrupted, burning minutes of
  reasoning time.
* **The Solution:** If an `extract` or `inspect` query with `--search` yields
  `totalMatches: 0` in the requested view, the inspection engine immediately
  checks the in-memory document against the alternate view (`accepted` $\leftrightarrow$ `rejected`)
  within the same scope (`range`, `indexes`, `table`, `body`). If matches exist
  in the alternate view, the response attaches an actionable guidance hint:

  ```json
  {
    "status": "ok",
    "command": "extract",
    "paragraphs": [],
    "selection": {
      "search": "3.2",
      "caseSensitive": false,
      "totalMatches": 0,
      "returnedMatches": 0,
      "returnedParagraphs": 0,
      "truncated": false,
      "nextAfter": null,
      "limit": 20,
      "around": 2,
      "softByteLimit": 49152,
      "oversizeItem": false,
      "hint": "0 matches in accepted view, but 1 match found in --view rejected. If searching for deleted text to restore, re-run with --view rejected."
    },
    "warnings": [],
    "machineReferencesAreNotUserLocations": true
  }
  ```

* **Symmetric Guidance:** If an agent searches in `--view rejected` for text
  that exists only in `--view accepted`, it receives symmetric guidance to
  re-run with `--view accepted`.
* **Zero Overhead:** The alternate-view check runs only when a search query
  produces zero matches, ensuring zero performance penalty on standard hits.

#### 2. Canonical Web Documentation URLs in CLI Help

* **The Problem:** In agent sandboxes, plugin runtimes, and containerized
  environments (such as `/mnt/skills/...`), only the bundled CLI executable and
  skill instructions are copied to disk. When `docx-redline apply --help` or
  `--help` returned bare relative documentation paths like
  `['AGENTS.md', 'docs/AGENT_FAST_START.md']`, AI agents assumed those files were
  present on the local filesystem and ran recursive searches
  (`find / -iname "AGENTS.md"`), wasting 20–30 seconds.
* **The Solution:** CLI help now outputs absolute, canonical GitHub repository
  URLs:

  ```json
  "documentation": [
    "https://github.com/AnsonLai/docx-redline-js/blob/main/AGENTS.md",
    "https://github.com/AnsonLai/docx-redline-js/blob/main/docs/AGENT_FAST_START.md",
    "https://github.com/AnsonLai/docx-redline-js/blob/main/docs/SKILL_AUTHORING.md",
    "https://github.com/AnsonLai/docx-redline-js/blob/main/docs/schemas/document-operations.schema.json"
  ]
  ```

* Agents immediately identify them as web references rather than local files,
  eliminating local disk scans while giving callers direct links to upstream
  contracts and guides.

### Verification & Test Coverage

A new dedicated end-to-end test suite
([`tests/agent_cli_deleted_clause_discovery_tests.mjs`](../tests/agent_cli_deleted_clause_discovery_tests.mjs))
reproduces the entire deleted clause restoration workflow against a masked
contract fixture:

1. **Blind Search:** Verifies that searching for a deleted section heading or
   body text in default accepted view returns `totalMatches: 0` with the
   actionable alternate-view hint.
2. **Guided Discovery:** Verifies that following the hint with `--view rejected`
   and `--around 2` returns the deleted match and surrounding context paragraphs
   with explicit `selectionRole` labels (`match` vs. `context`), `paragraphId`,
   and `fingerprint`.
3. **Restore & Wordsmith:** Verifies that applying a `restore` operation with
   content modification/truncation succeeds with complete status and zero
   validation issues.
4. **Post-Mutation Verification:** Verifies that the restored clause appears as
   active content in the accepted view of the generated package.
5. **Help Documentation:** Verifies that `apply --help` and global `--help`
   emit absolute GitHub documentation URLs.

### Backward Compatibility

- **Additive metadata:** `selection.hint` is an optional string property on the
  existing `selection` object. Existing callers ignoring unknown properties are
  unaffected.
- **Contract Stability:** CLI exit codes, command signatures, operation
  schemas, revision tokens, and receipt structures remain identical.
- **Reviewer Identity:** Author resolution (`--author`, `DOCX_REDLINE_AUTHOR`,
  `AI Redliner` fallback) remains unchanged.
